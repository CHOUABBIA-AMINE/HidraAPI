# HidraAPI Documentation Status Model

## Status

CURRENT — canonical governance rule.

| Status | Meaning |
|---|---|
| DRAFT | Being prepared; not approved as current authority. |
| CURRENT | Verified description of implemented/currently approved reality. |
| TARGET | Approved intended architecture/design not yet fully implemented. |
| DEFERRED | Explicitly postponed target capability; not a present implementation claim or P0 defect. |
| SUPERSEDED | No longer authoritative for current execution/current-state description; retained when evidentiary value exists. |
| HISTORICAL | Preserved record of an earlier state, decision, audit, or baseline. |
| EXECUTION_HISTORY | Preserved task/remediation record; not automatically current architecture or execution authority. |
| UNVERIFIED | Repository evidence is insufficient to establish the claim. |
| BLOCKED-DECISION | Execution cannot proceed without an explicit owner/business/operations decision. |

## Mandatory Separation

A document containing both CURRENT and TARGET material must label them clearly enough that a reader cannot mistake intended architecture for implemented reality.
